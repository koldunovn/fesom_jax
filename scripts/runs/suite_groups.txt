# Which suite group each test file belongs to.  <group> <path-from-repo-root>
#
# Grouped by COST, not by subsystem. The old grouping was "ice", "sharding", and "everything
# else" — and "everything else" is not a category, it is a default. It grew to 920 tests and
# 3:28 of wall time without anyone deciding that, because nothing reported per-test cost and a
# new file joined it by doing nothing. Cost is what the scheduler actually cares about.
#
#   unit      — pi mesh, closures, algebra, pytrees. Hundreds of tests, seconds each.
#   core2     — anything that assembles a CORE2 step or loads the CORE2 mesh/IC/forcing.
#               This is where the wall time is: a handful of tests, minutes each.
#   ice       — the assembled sea-ice step. Kept separate for MEMORY, not for time: the jit
#               cache of the whole suite plus the ice step exceeds a generous RAM budget in one
#               process.
#   sharding  — needs XLA_FLAGS=--xla_force_host_platform_device_count=4, and 300 GB: it OOM'd
#               at 209 GB against a 200 GB request on 2026-08-07, which read as a sharding
#               failure and was a scheduling one.
#   scripts   — the tests that live next to their scripts under scripts/tests/. ⚠️ These had
#               NEVER run in the suite: every runner globbed fesom_jax/tests/ only, so seven
#               files — including the 12 Task-4 mesh-diagnostic tests and the 7 horizon-scan
#               harness tests that the plan records as passing — only ever ran when somebody
#               invoked pytest by hand (found 2026-08-08). They are cheap; they are their own
#               group because they need the repo root on sys.path, not the package dir.
#
# ⚠️ EVERY test_*.py under fesom_jax/tests/ AND scripts/tests/ must appear here exactly once.
# fesom_jax/tests/test_suite_groups.py fails if one does not, so a new file cannot join the
# largest group by accident. Put a new file in `core2` if it touches data/mesh_core2,
# data/ic_core2* or build_surface_forcing; `unit` otherwise; `scripts` if it lives under
# scripts/tests/.
